# M0 foundation: proposed coding-agent packets

**Status:** proposed planning aid; no packet is approved or dispatch-ready. **Canonical IDs:** `workflow/tasks.yaml` schema v1. This document refines those six IDs; it does not create new DAG nodes or authorize wider paths. The PRD v1.0 is explicitly proposed, and this pack says it is not an implementation repository. The coordinator must secure the accepted baseline and locate/create the actual implementation repository before dispatch.

## Dispatch rules

- One coordinator assigns distinct coding sessions, read sets, isolated worktrees, and leases. Workers do not spawn agents. Review and test sessions are independent of implementing sessions. Only the Git broker mutates repository metadata.
- Before each assignment, read the approved packet, feature spec, relevant machine schemas and contract hashes, `docs/API_RECORD.md`, and impacted code. Verify installed tool versions, signatures and provider flags; enter version and evidence in `docs/API_RECORD.md` through a separately authorized scope. Its current entries are **TO VERIFY**. Do not treat a planned method or target command as an implemented API.
- A packet's source write scope must be narrowed from `workflow/tasks.yaml` and checked against its registry allowance. Runtime `.weave/runtime/<session-id>/` artifacts are controlled outputs, not a license to edit source outside the packet. Release file/resource leases only after a validated handoff; no terminal text or process exit advances a task.
- Every verification record needs exact command, platform, start/end timestamp, exit code, redacted stdout/stderr artifact path and hash. A passing check does not replace independent review, test verdict or broker integration. The packet report must match `contracts/schemas/task-report.schema.json` and be submitted through the documented `weave task report` workflow once its implemented transport and flags are verified; see decision DCR-M0-03 for the bootstrap interval.

## Actual concurrency schedule

`INF-001 → INF-002 → INF-003 → PTY-001 → {PTY-002 ∥ PROV-001}` is the M0 critical path from `workflow/tasks.yaml`. Each arrow means acceptance/integration plus frozen interface evidence, not merely agent handoff. Only **PTY-002 and PROV-001** are parallel M0 coding packets under the current DAG: their proposed source scopes and exclusive resources are disjoint. They must share the accepted PTY/API contract versions, use different worktrees, and avoid editing a shared daemon manifest or entrypoint. Independent read-only review/test preparation can occur earlier but cannot mark a downstream coding packet ready. Four sessions do not imply four concurrent writers.

## Decisions required before dispatch

1. **DCR-M0-01 — bootstrap path scope and CI.** `INF-001` promises CI and a workspace, but its registry write globs exclude `.github/**` and possible root manifests/lockfiles. Approve exact additional paths (or a different CI/workspace arrangement) and amend `workflow/tasks.yaml` before writing there. Do not silently place CI outside the lease.
2. **DCR-M0-02 — crate integration seams.** `PTY-001` is limited to `crates/weave-daemon/src/pty/**` and `PROV-001` to `crates/weave-provider/**`; real daemon module registration/dependencies and provider-to-supervisor wiring may require daemon entrypoint/manifest edits outside those scopes. Freeze the interface and prewire it in an upstream task, or approve narrowly named files and serialize any overlap. `PTY-002` likewise needs an agreed UI entrypoint owner.
3. **DCR-M0-03 — early structured reports.** `AGENTS.md` requires `weave task report`, while `MEM-002` (M1) is scheduled to implement that report validator/CLI. Define an approved provisional schema validator/report submission path for M0 or move the minimal report command into INF-003 with an explicit dependency/scope update. Do not label a stdout claim as accepted work.
4. **DCR-M0-04 — written dependency mismatch.** The Implementation Plan handoff shorthand says `INF-001 → INF-002/INF-003`, implying overlap, while its M0 table and `workflow/tasks.yaml` require INF-003 to wait for INF-002. Follow the registry order unless an approved DAG change is made; edit the shorthand for clarity.
